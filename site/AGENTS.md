# Prototype Instructions

Run the local server yourself and open the preview in the browser available to this environment. Do not give the user server-start instructions when you can run it.

Before making substantial visual changes, use the Product Design plugin's `get-context` skill when the visual source is unclear or no longer matches the current goal. When the user gives durable prototype-specific design feedback, preferences, or decisions, record them in `AGENTS.md`.

When implementing from a selected generated mock, treat that image as the source of truth for layout, component anatomy, density, spacing, color, typography, visible content, and hierarchy.

Build app UI in `src/`. Keep `.openai/hosting.json`, `worker/index.js`, `scripts/prepare-sites-build.mjs`, and `tests/sites-worker.test.mjs` intact so the same local prototype can be handed to Sites. Before a Sites handoff, run `npm run build` and `npm run test:sites`; the build must leave `dist/client/index.html`, `dist/server/index.js`, and `dist/.openai/hosting.json`.

Project media galleries default to a **justified photo grid** (Adobe Portfolio style), not bento: every image in a row renders at the same height, widths follow each image's real aspect ratio, nothing is cropped by default, and manual image order is preserved. Bento remains available as an opt-in editorial layout (`layout: "bento"` on a gallery block) for a project an editor deliberately wants to curate as a mixed-size composition — it is never the default. Supported gallery modes: `justified` (default), `full-width`, `split`, `uniform`, `bento` (opt-in only). See `docs/portfolio-decisions.md` for the full reasoning and rollout status; as of 2026-09-20 this has been prototyped on one project (`mongodb-the-next-generation-database`) only, pending Ayodeji's review before wider rollout.

**Bento is a deterministic CSS grid, not a measured one (2026-10).** `BentoGallery` (`src/App.jsx`) never measures rendered content — no `ResizeObserver`, `getBoundingClientRect`, `requestAnimationFrame`, image-load listener, or dynamically assigned `gridRowEnd`/`gridColumnEnd`. Each tile's size comes entirely from a fixed `size` → shape → CSS rule chain: `size` is one of five shapes (`square`, `landscape`, `portrait`, `feature`, `wide`), mapped via `bentoShapeFor()` in `src/bento.js` (old `small`/`medium`/`large`/`wide`/`auto` values from existing content still work, aliased to the new shapes — see that file). The CSS lives in `.gallery.layout-bento` in `src/styles.css`/`public/preview.css`: a 12-column grid with constant `grid-row: span N` per shape, no `grid-auto-flow: dense` (tiles always render in DOM/source order; a sparse grid can leave a small gap rather than visually reorder). `.bento-tile` sets `align-self: stretch` explicitly — don't remove it, it's load-order-sensitive: without it, a tile is sized by its flex content instead of its grid-row span, and collapses to 0px until its (often lazy-loaded, often below-the-fold) image has actually loaded. Each image optionally sets `fit` (`contain`, default — never crops; or `cover`, only when deliberately chosen per image) and `position` (anchor point when `cover` crops). On phone widths (≤560px) the grid becomes a single natural-ratio column and `fit`/`position` are force-overridden back to `contain`/`center` regardless of the per-image setting, since a one-column stack has no "composition" left to preserve. `uniform` galleries render via a separate, simpler `UniformGallery` component (same-size CSS-grid tiles, no shape logic) — they used to silently fall through to `BentoGallery`, which no longer applies since bento is shape-specific now. See `docs/portfolio-decisions.md` for the full before/after and the per-project layout audit.
