# Project content audit

Phase 1 deliverable for the portfolio-project-restructure task. Audited 2026-10-27 from `site/content/projects/*.json`, `site/content/experiments/*.json`, `site/content/reel.json`, and `site/content/settings.json` on `origin/main` (commit `4365b90`, post media-reorg PR #4), cross-referenced against `docs/content-and-asset-inventory.md`, `docs/portfolio-decisions.md`, and `ROADMAP.md`.

**How to read this doc.** It is the per-project ground truth the restructure plan (`docs/portfolio-restructure-plan.md`) is built from. Nothing here is invented — every "Role," "Outcome," and "Missing information" cell is either copied verbatim from the current content JSON or flagged as absent. Where this task's instructions proposed new copy, see the restructure plan instead; this document records **current state**, not proposed state.

All 21 projects are `published: true`. (Correction to `site/README.md`, which still says Linx and the MongoDB beliefs storyboard are drafts — both were published 2026-10-26 per `ROADMAP.md` and confirmed directly in their JSON files this pass.)

**Structural note carried through every row below:** the schema has one `summary` field, rendered as both the homepage card description (`.card-summary`) and the page-top subhead (`<p className="summary">` in `Project()`, `src/App.jsx`). There is no separate `cardDescription` vs. page-summary field today — they are, by construction, identical text. This is not a bug, but it means any copy rewrite in Phase 2 has to serve both a 2-line-clamped card and a page subhead at once, or the schema needs a second field. Flagged once here rather than on every row.

## Category audit

Current distribution across the 21 published projects:

| Category | Count | Projects |
|---|---|---|
| Brand Systems | 9 | Security Brand Experiences, AI-Assisted Design Systems, Meta Connect, Performance Marketing Systems, Event Brand and Experiential, Enterprise Brand Campaigns, Global Rebrand Launch Experience, Modern UX for a Leading Developer Platform, Linx Brand Illustration System |
| Technical Storytelling | 5 | Frictionless Product Onboarding, Designing for a Developer Platform, Innovation Without Limits, Technical Concept Visualization, Translation Transformation eBook |
| Communications | 4 | Culture and Internal Brand Storytelling, MongoDB Company Values Launch Campaign, Executive Presentation Systems, Creative Communications for Lyft |
| Partnerships | 3 | Global Partnership Campaigns (Visa), Enterprise Integration Campaigns, Airline Partnership Experience Design (Lufthansa) |

Confirms the task's observation: **Brand Systems is 43% of the catalog** and spans event work (Event Brand and Experiential, Global Rebrand Launch Experience), campaign work (Enterprise Brand Campaigns), web work (Security Brand Experiences, Modern UX for a Leading Developer Platform), illustration (Linx), and a keynote (Meta Connect) — it is not filtering anything meaningfully on the homepage today, since selecting it returns nearly half the catalog in unrelated media types.

**Recommendation (minimal revision, not a new framework):** keep the existing 4 categories — Brand Systems, Partnerships, Technical Storytelling, Communications — they're accurate labels, just unevenly loaded. Once projects move under company collections, categories stop being the primary navigation axis (company collections + the project/standalone/additional-work tiers are) and become a secondary cross-company filter, which resolves the overload without inventing new category names. If Ayo wants categories to keep working hard as a homepage filter even with collections in place, the only candidate split worth considering is pulling "Events and environments" out of Brand Systems as its own category — but that would need to apply consistently across every company (AppOmni, MongoDB, TripActions/Navan, DocuSign, Apollo all have event work), which is a bigger call than this audit should make unilaterally. Flagged for Ayo's decision, not applied.
