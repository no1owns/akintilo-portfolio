## How this audit was done, and its limits

This session's network egress is restricted to GitHub, npm/PyPI-class registries, and a few other allow-listed hosts. Direct requests to `www.akintilo.com` and `preview.akintilo.com` were blocked by the environment's proxy (`EGRESS_BLOCKED`), so **the live Adobe Portfolio site and the live preview were not fetched or re-verified in this session.** Where the task asked for a live side-by-side comparison, this document instead relies on:

- `site/README.md` and `site/design-qa.md` in `akintilo-portfolio`, which record an earlier, in-browser comparison against a "user-selected Option 1 screenshot" of the Adobe site (dated September 13, 2026) and confirm the migration already captured the Adobe project list (19 projects imported, 17 published).
- The structured content in `site/content/projects/*.json` and `site/content/settings.json`, which is the current system of record for the target repo.
- `web-portfolio`'s `llms.txt`, `portfolio.html`, and its per-case-study HTML pages, which describe an independently-redesigned personal site built from the same underlying career history, plus a large library of original media in `web-portfolio/images/`.

**Recommendation:** before Phase 3 QA, someone with browser access to `https://www.akintilo.com` and `https://preview.akintilo.com` (Ayodeji or ChatGPT) should do one direct side-by-side pass to confirm nothing has changed on the Adobe site since the September 13 reference screenshot, and to sanity-check the preview against this document's findings.

## Gallery layout audit

As of 2026-09-20, every one of the then-19 projects' `gallery` blocks used the default `layout: "bento"` (no project set an explicit `layout` field). `src/App.jsx`'s `BentoGallery` component computes column spans from each image's aspect ratio (or an editor-set `small/medium/large/wide` size) and packs rows densely — this is a real, working masonry, not a placeholder. The CSS also defines `.gallery.layout-uniform` selectors for narrow breakpoints, but no component set `layout: "uniform"`, so that mode was effectively unused.

**Update 2026-10-01:** two projects now explicitly set `layout: "justified"` — `mongodb-the-next-generation-database` (the original prototype, converted from bento) and `meta-connect` (built justified from creation, since it's new content rather than a bento conversion). **Update 2026-10-21 (round 2):** the remaining 8 published bento projects were converted — Security Brand Experiences, Performance Marketing Systems, Event Brand and Experiential, Enterprise Brand Campaigns, Innovation Without Limits, Lyft, Dream Big, and Frictionless Product Onboarding — after Ayodeji flagged that the rest of the site's galleries "don't structure the images into grids well." The root cause: `BentoGallery` forces every tile into one of a few fixed-aspect-ratio boxes, so a gallery mixing portrait social graphics, square posts, and landscape photos (every one of these 8 projects) renders most images tiny and centered inside large empty gray boxes, since `fit: "contain"` never crops to fill. Justified sizes every image to its real aspect ratio instead, eliminating that waste. **All published projects are now justified; `BentoGallery` is no longer used by any published project** (it remains available as opt-in for a future project that deliberately wants a mixed-size editorial composition — see `site/AGENTS.md`). Dream Big and Frictionless Product Onboarding, previously flagged as needing Ayodeji's pick between uniform and justified rather than a default, were confirmed as justified directly. The 2 unpublished drafts (`linx-security`, `mongodb-beliefs-storyboard`) are still bento, untouched since they're not live.
